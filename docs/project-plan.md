# RecLab Agent 完整设计与八周实施计划

确认日期：2026-10-19。本文记录已确认的设计与验收目标，不表示全部功能已经实现。实现状态以测试、运行记录和学习文档中的阶段记录为准。

## 1. 定位与交付目标

RecLab Agent 面向推荐算法工程师，完成“理解问题 → 检索与诊断 → 提出假设 → 修改代码 → 隔离运行 → 独立评测 → 保留或否定方案 → 报告”的研究闭环。

典型任务：分析 SASRec 的低频商品表现，在给定训练预算内提出并实现一种修改，比较验证集结果，说明是否值得保留。

最终交付诊断与证据、实验计划、真实代码 Diff、运行配置、独立评分结果、保留或回退结论、完整 Trace、费用和复现入口。正确识别负结果也是有效产出，不预设算法或多 Agent 一定带来指标提升。

已确认约束：周期 6–8 周，每周 25–35 小时；第 6 周形成可演示版本，第 8 周完成正式评测；目标预算 1500 元、硬上限 2000 元；本机运行工作台，云端 Linux 主机执行 CPU/GPU 容器任务。

## 2. 总体架构

数据流：Web/CLI → 任务控制器 → Agent 编排 → 资料和证据工具 → 候选源码工作区 → Docker Worker → 预测与产物 → 独立评分器 → Reviewer → 下一轮实验或最终报告。

| 子系统 | 设计 |
|---|---|
| 控制平面 | 本机 Python 3.11+、FastAPI、SQLite；管理任务、预算、状态、产物 |
| 编排 | 保留自研 Runtime 单 Agent 基线，增加 LangGraph 状态图与持久化 |
| 模型接入 | 复用 ModelBackend/Responses 适配器；通过配置冻结模型版本和价格 |
| 推荐后端 | 固定版本 semantic-id-rec 加独立 Adapter，不依赖相邻源码目录 |
| 执行 | 专用 Linux 主机上的 Docker Worker；通过 SSH 接入，禁止宿主执行候选代码 |
| 检索 | BM25、向量召回、RRF 与 Reranker；返回来源、段落和内容哈希 |
| 展示 | FastAPI/Jinja2/轻量 JavaScript，SSE 展示任务、Diff、实验、报告、Trace |
| 存储 | SQLite 状态；内容寻址文件产物；大数据、权重、日志不提交 Git |

## 3. Agent 模式与研究过程

三种可切换模式复用同一工具、预算和评分器：单 Agent ReAct；Planner–Executor；Planner–Executor–Reviewer。

Planner 形成假设、对照与停止条件；Executor 修改代码、运行和诊断错误；Reviewer 核对证据、指标口径和结论，最多要求一次复核，无权扩大预算或修改评分器。默认模式在开发集上选择，冻结后再做测试。

工具包括证据清单、指标读取、分桶统计、实验比较、资料检索、工作区检索/读取/补丁/校验、作业提交/查询/取消和产物收集。

编排状态与跨实验知识分别管理；checkpoint 保存当前计划、补丁、作业和预算，知识库只收录已复核事实。记录工具参数、实际 Diff、结果和简明决策依据，不把未验证的模型说法当事实。

## 4. 自主编码与执行边界

每轮循环：读取源码 → 提出修改及预期 → 应用补丁 → 语法检查 → Smoke Test → 短训 → 独立评分 → 修复、接受、否定或停止。

可编辑文件为登记的模型、训练、损失、采样和配置；数据协议、评分器、执行器、依赖锁定和基线快照不可修改。每个候选生成独立内容哈希快照，最终输出可审核补丁，不自动覆盖推荐仓库主分支。

默认单任务最多 2 个候选、6 次补丁、3 次训练（含需要补跑的基线）；短训每次最长 10 分钟、训练总预算 30 分钟、并发 1。完整确认训练使用单独的长任务配置。失败返回结构化原因，达到预算后输出已验证发现和未完成内容。

专用云主机容器采用非 root、禁网、只读根文件系统、CPU/内存/进程/时间限制。候选仅获得源码、所需数据和输出目录；不获得 API Key、SSH 凭据、Docker Socket 或测试标签。venv 和普通子进程不作为安全沙箱。

执行分三段：训练容器输出权重和配置；独立推理容器输出逐用户排名；外部固定评分器读取预测与标签并重算指标。候选自报指标只作诊断。加载候选权重和执行候选推理也必须留在隔离环境中。

## 5. 数据与模型接入

首版真实训练支持 Popularity 和 B1 SASRec。B2、G2 在恢复权重和依赖后先接固定推理/诊断，再决定训练扩展。

三个独立数据 Profile：synthetic-smoke 只验证链路；beauty-small 固定抽取 2048 名用户后按既定协议预处理，用于短训；beauty-full 沿用完整 Beauty 协议，用于最终确认。冻结数据、训练目录、有效用户、过滤规则和哈希，不跨 Profile 比较指标。

train/valid 用于开发反馈；测试标签不进入候选容器、RAG 或工具输出。最终冻结源码、配置、权重和环境后才做测试，测试分数不再用于该轮修改。旧 Beauty 测试集已有使用历史，明确标注复用性质，不宣称全新未见数据泛化。

新模型和数据首次接入需提供：数据与划分、训练/预测入口、基线配置、固定评分协议、可编辑文件、依赖与资源需求。相同任务更换数据/模型时只替换 Adapter；任务从下一商品预测改为 CTR 等目标时，同时增加任务与评分适配器。

核心验收包括：现有 SASRec 开发后，再接一个未参与开发的新模型或数据，检查核心 Agent 是否无需修改即可开展实验。

## 6. 检索与事实引用

知识库收录模型说明、数据协议、源码说明、历史实验和已复核报告；结构化数值仍通过工具读取。禁止索引测试答案、测试标签或未核实的模型结论。

默认按标题/段落切分，约 500 字、80 字重叠；BM25 与向量各取 20 条，RRF 合并最多 30 条；bge-small-zh-v1.5 编码、bge-reranker-base 重排，返回前 5 条。正文保留文档版本、段落 ID、哈希与实验来源。

Linux 参考环境使用 FAISS CPU；Windows 可用 NumPy 精确索引，验证同一语料检索一致性。实现 BM25、注入向量测试和真实 BGE 运行必须分别标注，不把未配置的向量检索降级后称为 hybrid。

## 7. 接口、持久化与可观测性

| 契约 | 内容 |
|---|---|
| TaskSpec | 问题、数据/基线引用、工具范围、预算、评价协议 |
| ExperimentPlan | 假设、修改、对照、预期、停止条件 |
| ToolResult | 结果、结构化错误、证据与产物引用 |
| JobSpec/JobResult | 源码、数据、镜像、配置、种子、资源与状态 |
| ArtifactRef | 内容哈希、类型、来源实验、划分和版本 |
| ResearchReport | 已验证发现、假设、比较、限制和后续建议 |

保留原 CLI；新增 run/status/cancel/resume/report/eval 研究命令。Web 使用同一服务接口，支持提交任务、查询、SSE 和报告下载。

每次运行独立 run_id，作业身份绑定源码、数据、镜像、配置和种子。恢复时先查询已有作业，避免重复启动；暂停节点与执行节点分开。超时、取消、OOM、异常预测、断线和预算耗尽均有明确终态。

## 8. 评测与验收

原 15 项任务属于工具合同测试，不是端到端 Agent 成功率。原三份带已知结论的 JSON 用于开发与回归，不用来证明未见任务泛化。

| 层级 | 设计与指标 |
|---|---|
| 工具和协议 | 离线确定性测试：计算、权限、状态、恢复、幂等 |
| 诊断和规划 | 30 开发 + 30 冻结测试；按证据场景划分，不只改写问法 |
| 检索 | 标注段落；Recall@5、MRR、引用正确率 |
| 真实编码 | 4 个小任务 × 固定配方/单 Agent/多 Agent × 2 次重复 |
| 推荐质量 | 冻结 B1 与最终候选各 3 seeds，NDCG@20、Recall@20、分桶与波动 |

四类编码任务：修复注入训练/推理错误；验证序列处理；实现损失/正则修改；实现仅依赖训练统计的采样修改。诊断覆盖矛盾证据、信息不足、负结果、工具失败和预算耗尽。

大规模诊断用缓存产物；真实训练集中在少量编码任务。对照使用相同模型、数据、工具和预算。工具集合匹配、模型裁判、答案流畅度均不能单独判成功；事实结论需逐项核对数值和来源。

验收目标：至少一个真实修改—报错—修复—运行—评分闭环；同时有有效改进与合理否定案例；冻结诊断任务成功率目标不低于 80%；权限、标签隔离、评分和重复启动测试全部通过；结果与补丁均可追溯。目标数值不是已取得的结果。

## 9. 八周实施与学习路线

| 周次 | 交付 | 必须掌握 |
|---|---|---|
| 1 | 恢复数据基线、冻结协议、独立评分、云端能力核验 | 数据泄漏、推荐指标、复现、产物身份 |
| 2 | 工作区、补丁、Docker Worker、异步作业和预算 | 容器、生命周期、超时、幂等 |
| 3 | 单 Agent 编码实验闭环与真实案例 | Function Calling、结构化输出、调试、停止 |
| 4 | 混合检索、重排、引用和检索评测 | Embedding、BM25、RRF、检索误差 |
| 5 | 多 Agent、持久化、断线恢复 | 状态图、通信、复核、消融 |
| 6 | Web/CLI，任务、Diff、实验、报告、Trace | FastAPI、SSE、服务/作业边界 |
| 7 | 冻结任务、基线对照、故障与成本报告 | Agent 评测、配对比较、统计不确定性 |
| 8 | 最终模型、正负案例、录像、README、面试材料 | 架构取舍、失败分析、结果表达 |

各阶段同步本地学习路线和飞书：本周实现、必须理解、关键实验、面试问题；区分设计、实现、测试、真实模型验证四类状态。

预算目标：模型 API/评测约 700 元，云实验约 600 元，存储与预留约 200 元；硬上限 2000 元。先用小试验校准费用，达到边界停止新增任务。

PRTA 个性化推荐工具选择是后续独立任务；MLE-bench 后续复用任务、工作区、执行器与产物协议，增加提交和官方 grader。首版不宣称已完成适配。不以大模型训练/RLHF、供应链业务或高并发平台作为首版主线。
