# RecLab Agent 学习路线与项目记录

这份文档服务于两个目标：完成一个可演示、可评测的推荐实验 Agent；覆盖 AI Builder（模型方向）岗位要求中的 Agent、模型评估、生产落地和跨团队表达能力。

## 当前阶段：受控运行与离线评测

### 本阶段已经实现

- Agent 使用函数调用读取推荐实验的结构化证据，并形成诊断结论。
- 每个任务可以配置 `allowed_tools`，模型只能看到允许的工具；执行层仍会再次校验，拒绝越权调用。
- 每次运行记录 JSONL 轨迹，包括模型轮次、工具参数、工具结果、证据路径、错误与耗时。
- 保存的轨迹可以离线 replay，无需再次调用模型即可复算评测结果。
- 评测指标包含任务完成、工具选择 Precision/Recall/F1、工具错误率、证据引用率、越权次数和工具延迟。

### 必须学会的四个概念

#### 1. Tool Calling Loop

一次完整循环是：用户问题 → 模型选择工具和参数 → 确定性代码执行工具 → 结果返回模型 → 模型继续规划或输出答案。

必须能够解释：

- 为什么数值计算放在 Python 工具中，而不是依赖大模型心算；
- `function_call` 和 `function_call_output` 如何通过 `call_id` 配对；
- 为什么需要最大轮次、重试和结构化错误；
- 模型负责规划，工具负责事实，这两部分如何分工。

对应代码：`reclab_agent/runtime.py`。

#### 2. 最小权限与双层防护

最小权限指每个任务只获得完成任务所需的工具。RecLab Agent 在两层实施限制：

1. 模型层：只把白名单中的工具 Schema 发给模型；
2. 执行层：即使模型仍构造了越权调用，也返回 `TOOL_NOT_ALLOWED`。

必须能够解释为什么仅隐藏工具 Schema 不够：模型输出、上游数据或运行时都可能异常，执行层必须独立校验。

对应代码：`function_tools(..., allowed_tools)` 与 `AgentRuntime.run(..., allowed_tools)`。

#### 3. 可观测轨迹与离线 Replay

生产 Agent 不能只保留最终答案。轨迹要能回答：模型调用了什么、参数是什么、工具返回了什么、用了哪些证据、哪里失败、耗时多少。

Replay 的价值：

- 不重新支付模型费用即可复算指标；
- 对比 Prompt、模型版本或工具版本；
- 定位线上失败并形成回归样本；
- 为后续 AB 实验和监控告警提供数据。

对应代码：`TraceWriter`、`load_trace`、`replay_trace`。

#### 4. Agent 评测不是只看答案

当前指标分别衡量：

- `completed`：是否正常完成；
- `tool_selection.f1`：是否选对工具，同时避免多余调用；
- `tool_error_rate`：调用参数或执行是否稳定；
- `answer_evidence_citation_rate`：最终答案是否明确引用实际读取的证据；
- `policy_violations`：是否发生越权；
- `tool_latency_ms`：工具调用的总延迟和最大延迟。

面试中要强调：一个 Agent 即使最终答案碰巧正确，如果证据不可追踪、经常越权或成本失控，也不能进入生产。

## 与 AI Builder（模型方向）JD 的对应关系

| JD能力 | RecLab Agent 证据 |
|---|---|
| Prompt、RAG、Agent应用 | 工具调用 Agent、受控证据检索与结构化回答 |
| 模型训练、评估、部署全流程 | 当前完成评估与运行时，后续补模型版本对比和服务化 |
| 建立模型评估体系 | 任务集、工具选择 F1、证据引用、错误、延迟、安全指标 |
| 推动持续优化 | JSONL 轨迹沉淀失败案例，离线 replay 支持回归评测 |
| 从算法选型到工程落地 | 推荐实验诊断问题被拆成工具、策略、运行时与测试 |
| 风控场景优先 | 最小权限、越权拒绝、审计轨迹可迁移到风控 Agent |

## 你现在应该能回答的面试问题

1. 为什么你的项目需要 Agent，而不是普通脚本或固定工作流？
2. 如何防止模型调用不该调用的工具？
3. 如何判断一次 Agent 运行是“高质量”的？
4. Prompt 或模型升级后，如何证明新版更好且没有回归？
5. 如果线上答案错误，如何通过轨迹定位到规划、参数、工具还是证据问题？
