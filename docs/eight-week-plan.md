## 目标与交付

2026-10-20执行环境决定：先使用已验收的本机 WSL2 Linux Docker CPU 接通 Agent 自主编码闭环，再补云端 GPU。云端容器与 GPU/Beauty 新训练验收继续保留为迁移阶段的必要检查；近期开发不因当前 AutoDL 无 Docker 而暂停，也不把本机结果视作云端通过。

面向推荐算法工程师，完成理解问题→检索/诊断→假设→修改代码→隔离运行→独立评分→保留/否定→报告的研究闭环。交付轻量Web与CLI、可复现实验、真实代码Diff、独立评分、Trace、正负案例和面试材料。

既有基础：推荐算法/PyTorch经验、semantic-id-rec源码、证据工具与状态化Runtime。当前三份历史JSON与15项参考调用只用于开发和工具合同回归，不是端到端Agent能力证明。

- 董听负责学习、验证设计和结果判断；Codex协助实现、测试和记录。是否保留候选由独立指标与约束判断。

## 关键路径与并行工作

关键路径：数据/评分协议→隔离执行→单Agent编码→持久化与复核→工作台→正式评测与验证集结果复核。检索可在数据和来源协议稳定后并行；界面可以提前做，但不能代替真实执行验收。

前置未完成则顺延相应实验，不把mock或合成fixture当作真实模型验证。每周文档独立记录计划、实际、证据和调整；更改数据、评分器或任务范围后重新冻结相关基线。

## 全局实验边界

候选只编辑登记的模型/训练/采样/配置；数据协议、评分器和执行器不可改。代码仅在Linux Docker隔离运行，测试标签不进入候选环境。正式验证集指标由独立评分器从逐用户预测重算，基线与候选使用同一个固定随机种子；交付时冻结源码、配置、权重和评分证据，不要求另行测试集评估。

预算契约默认单研究任务最多2个候选、6次补丁、3次训练，单次作业10分钟、总作业预算30分钟，并发1，实际以任务配置为准。基线与候选使用同一个固定随机种子进行训练和验证集评估，每个方案默认训练一次；3次训练是不同方案的合计预算，不是3个种子重复。训练按epochs、早停和时间预算执行。超时、取消、OOM、断线、无效预测与预算耗尽均有明确终态。

## 评测与最终验收

- 工具/协议：计算、权限、标签隔离、状态、恢复和幂等全部通过。
- 诊断/规划：30开发+30冻结测试，按证据场景划分；目标成功率不低于80%，未达标如实报告。
- 检索：标注文档/段落，报告Recall@5、MRR、引用与事实支持。
- 真实编码：4类小任务，固定配方/单Agent/多Agent各重复2次；比较同预算完成率、质量、时延与费用。
- 推荐质量：冻结B1与最终候选，使用同一个固定随机种子各训练和验证集评估一次，报告NDCG@20、Recall@20和分桶指标；不保证或预设提升。
- 迁移：新模型或新数据完成Adapter后，核心Agent无需改写即可开始实验；任务变化时适配评分器。
- 作品：至少一条真实修改—报错—修复—运行—评分链路，正/负案例、运行说明和可追溯材料齐全。

## 预算与触发处理

目标总额1500元，硬上限2000元：模型API/评测约700元、云实验约600元、存储和预留约200元。先小样本校准实际价格与时长，不能把这些分配额当成已支付费用。

费用接近边界时优先保留最终验收预算，减少重复推理与大型训练；达到上限停止新增任务并报告已有结果。云环境不具备Docker隔离时暂停候选代码实验，先完成不受影响的工具/检索/协议工作，不降级为宿主运行候选。
