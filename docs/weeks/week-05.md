## 必须学会

本篇讲设计原理。下面的状态与作业例子是概念伪例，不表示LangGraph或真实多Agent收益已经实现。

### 先想一个问题

单Agent已能调用工具，为什么还要增加Planner、Executor和Reviewer？如果三者只轮流重复同一段话，增加的可能只是延迟和费用。角色划分必须对应真实职责：谁提出可检验假设，谁执行实验，谁检查结论是否由证据推出。

固定workflow可以规定“读取指标→训练→报告”，其中也能调用LLM；Agent允许模型根据观察选择下一步。把workflow写成图，并不会自动产生自主性；把三个节点命名为三种角色，也不会自动产生独立复核。

### 原理一：角色靠输入、输出和权限区分

Planner输出假设、对照、修改范围和停止条件；Executor接收计划，提交补丁、日志和独立评分结果；Reviewer检查口径、证据和预算，输出接受、否定或一次复核请求。Reviewer不能修改标签、评分器或扩大预算。

例如候选低频Recall增加，但整体NDCG下降。Reviewer应核查是否违背目标、种子与数据是否一致，再解释收益与代价。它不应仅因“增加了一个Reviewer”就被视为正确。多个角色共享同一模型时仍可能犯相关错误，因此需要确定性校验与真实评测。

### 原理二：状态、checkpoint和store不是一回事

`RunState`是本次运行的当前事实，例如`{plan_id, patch_hash, job_id, remaining_budget, next_step}`。它回答“现在走到哪里”。不要只保存聊天文本，否则恢复时难以确定哪些动作已经执行。

**Checkpoint** 是同一线程图状态的快照，支持恢复执行；**Store** 保存应用定义的跨线程知识，例如已复核实验经验。一个负责接续当前任务，一个帮助新任务利用历史。内存checkpointer只能验证流程，进程重启后不能提供持久恢复。[LangGraph 官方持久化说明](https://docs.langchain.com/oss/python/langgraph/persistence)

内容寻址产物另有职责：权重或报告由哈希引用，状态里存引用，不复制大文件。checkpoint不是训练权重，也不是历史知识库；数据库里有一条run记录，也不等于整个图已能恢复。

### 原理三：恢复不能重复启动实验

假设节点先启动训练，再等待人工输入。若恢复从节点开头执行，训练可能被启动第二次。官方文档明确指出中断恢复会重跑相关节点，之前的副作用需要幂等或拆分。[LangGraph 官方中断说明](https://docs.langchain.com/oss/python/langgraph/interrupts)

概念伪例：`key=hash(source,data,image,config,seed)`；执行`submit_or_get(key)`，同一key只对应一个逻辑作业。启动前先持久化意图，worker用唯一键提交或查询已有作业，恢复后继续poll。只在Python里“先查再启动”有并发竞争，不能保证幂等；预算扣减也要绑定作业身份，防止重试扣两次。幂等不是把所有异常吞掉，而是重复请求不产生第二份副作用。

### 对照 RecLab 阅读

`core/session.py` 已有有界 Function Calling 循环与 Trace；`agents/` 中的计划执行和反思策略共用会话、工具权限和总轮次，工具接口与实现位于 `tools/`。这些能力不等于持久化多 Agent 状态图，Trace 回放本身也不等于现场续跑。`storage.py` 的 RunStore 把状态和事件存入 SQLite，ArtifactStore 校验内容哈希；它们是自研存储组件，不应直接称为 LangGraph Checkpointer 或长期语义记忆。接入状态图时需要明确映射，并测试断线窗口。

旧 `AgentRuntime` 导入已移除，单 Agent 基线使用 `ReActAgent`。`OptimizationAgent` 注入研究计划和目标模型上下文，帮助策略使用同一份任务事实；跨进程状态、预算恢复与实际实验收益仍需分别验收，已有模型实验协议保持不变。

共享状态应记录计划、实验引用和结构化复核，而非各角色维护互相冲突的“事实”。设置总调用预算、复核次数和终态，避免角色无限讨论。

### 怎样证明多Agent值得

同一批任务、模型版本、工具、数据和总费用上限，对比单Agent、Planner–Executor及加入Reviewer。Reviewer费用必须计入总预算；还应给单Agent同预算的额外反思机会。报告任务成功率、错误结论、有效实验数、延迟与费用，按相同任务配对比较。开发集确定模式，冻结测试集检验；不要把角色更多、回答更长当成收益。

### 练习与参考答案

1. “完成两次实验、还剩一次额度”应存在哪里？“某损失在固定数据上无收益”又在哪里？
2. worker已接受作业，但控制端尚未写入job_id便断线，恢复应怎样处理？
3. 多Agent花2元成功8题，单Agent花1元成功7题，能否宣称多Agent更优？

参考答案：①前者进入RunState及持久checkpoint；后者复核后连同数据、代码和指标引用进入跨任务知识，不能泛化成所有数据都无收益。②使用已持久化的提交key向worker查询或幂等提交，不能盲启新训练。③不能；还需同任务、同预算对照与重复运行，呈现质量与成本权衡。

### 本周概念检查清单

- 角色分工：Planner写计划，Executor执行，Reviewer检查证据；角色数本身不是收益。
- 状态图与Checkpoint：状态决定下一步，持久化使重启恢复成为可能；内存存储不等于重启恢复。
- 共享状态与通信：计划、实验、反馈使用结构化字段，避免多份互相矛盾的自由文本。
- 复核与恢复：Reviewer限制权限与轮数；恢复节点可能重跑，副作用必须幂等。
