# 第7周学习正文：怎样证明Agent真的有用

本篇从推荐实验熟悉的“同口径比较”出发，学习Agent评测。数字均为**教学示例**，不是RecLab实测成绩；完整评测矩阵仍需实际执行。

## 先思考一个问题

Agent调用了正确工具、生成了漂亮报告，但把“验证集提高”写成“线上收益提高”，算成功吗？不算。工具执行、证据理解、实验实施、结论可信和推荐收益属于不同层次，不能用一个工具调用F1代替全部能力。

## 原理：分层定位错误

工具合同测试检查输入、输出、数值和权限；检索测试检查相关段落是否召回；诊断任务检查事实、假设与证据；编码任务检查补丁能否运行、协议是否被改坏；推荐评测最后检查实际预测质量。每层都有独立分母。15项工具测试全过，不能记为15个端到端研究任务成功。

工具路径也可能不唯一。先读统计再检索、先检索再读统计，都能得出正确结论。因此同时看最终任务成功、必要约束、引用与事实正确性，工具F1仅辅助解释。LLM裁判容易受措辞影响；可计算结果交给评分器，关键事实由人工核对，裁判用于补充分析。

## 原理：模型数据与Agent任务都要防泄漏

有两套划分：推荐模型的train/valid/test，Agent任务的开发/冻结测试。首版没有专门训练Agent参数，开发任务用于改Prompt、工具和流程；未来训练工具选择策略，才另建任务train集。

模型test标签不能参与调参；Agent测试答案也不能进入检索库。把同一证据场景改写为十种问法再随机划分，仍可能泄漏答案结构。应该按场景或实验来源分组划分。若用冻结测试反复挑默认模式，它实际上变成开发集，必须诚实标记并准备新的最终任务。[数据泄漏原则](https://scikit-learn.org/stable/common_pitfalls.html#data-leakage)

## 原理：同预算比较，才能解释收益

固定Workflow、单Agent、单Agent＋RAG、主研究者＋独立审计应使用相同模型、工具权限、任务和评分协议，设置相同总token、训练次数与时间上限。审计消耗的预算计入总额。只限定“每个角色10步”，会让多Agent获得更多资源。

实际花费仍可能不同，必须同时报告质量、成本、时延、失败；不能把失败任务从分母移除。先在开发集选配置，再冻结测试。同预算不代表每次都要烧完预算，节省资源也是结果。

## 手算例子：配对bootstrap保留同一用户

四名用户的候选减基线NDCG差值为：

```text
用户       A      B       C      D
差值     0.02   0.01   -0.01   0.00
平均差 = (0.02 + 0.01 - 0.01 + 0) / 4 = 0.005
```

一次重采样抽到A、A、C、D，差值均值为0.0075。必须让两个模型使用同一组抽样用户，这就是配对；分别抽样会破坏用户难度的对应关系。[SciPy配对定义](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.bootstrap.html)

这四人的有放回抽样共有4⁴=256种等概率索引序列。枚举均值，采用最近秩百分位法，95%示例区间为[-0.005, 0.015]。它跨过0，说明当前观测不足以支持稳定正收益；不是证明两个模型完全相等。四人例子只解释算法，样本太小不能支撑实际结论。

```text

```

## 在RecLab里边学边做

先对相同任务逐项对齐，再计算成功率差；任务存在共同场景时按场景重采样，不能把改写问题视为独立样本。用户bootstrap用于推荐指标，不用于替代Agent任务评测。

1. 基线成功18/30，候选成功24/30，能直接声称“稳定提升20%”吗？
2. 额外给研究者三次训练，分数更高，证明了什么？
3. 区间跨0，报告如何写？

## 参考答案

1. 观测提高20个百分点，相对提高约33.3%；仍需看配对任务、失败、区间及代表性，不能直接声称稳定。
2. 证明了更高资源配置的表现，尚未隔离审计贡献。补同预算对照。
3. 写明点估计、区间、样本和限制：“当前结果不确定，尚无充分正收益证据”；保留所有负结果与费用。
