# 第3周学习正文：模型怎样真正调用工具并修复实验

本节基于当前 `core/session.py`、`agents/react_agent.py`、`tools/`、`workspace.py` 和测试讲解。已有诊断工具循环、多种 Agent 策略与受控补丁/实验适配；“模型自主改代码—真实训练—独立评分”仍需配置目标模型和可信实验 runner，下面完整实验流程为设计示例。旧 `AgentRuntime` 导入已移除，原工具循环使用 `ReActAgent`。

## 一、问题：模型说“我运行了训练”，等于真的运行了吗？

Function Calling 把语言决定变成程序可处理的请求。模型提出工具名和参数，宿主程序执行，工具结果再送回模型。模型不能靠一句话完成文件修改或启动 GPU。你可以把模型理解为策略：根据历史选择动作；工具是环境转移；返回结果是观察。真正的实验事实来自环境，而非策略对自己的描述。[函数调用官方指南](https://developers.openai.com/api/docs/guides/function-calling)

当前 `ReActAgent` 通过 `RunSession` 完成循环：收集模型输出中的调用，解析参数，检查权限，调用工具，再追加 `function_call_output`。下一轮模型能据此选择继续调用或结束。输出历史也必须保留，让模型知道自己提出过什么。计划执行与反思策略复用同一会话，规划、执行、评价和修订共同消耗本次运行的模型轮次预算。

**与现有代码一致的消息形状示例：**

```json
{"type":"function_call","name":"diagnose_beam_gap","arguments":"{}","call_id":"c1"}
```

结果带回同一个 `call_id="c1"`。它是一次调用与结果的关联键，不是推荐模型 ID，也不是整个研究任务的 `run_id`。同一工具连续调用两次，仍应能分别匹配结果。

**练习。** 模型同时提出 c1、c2 两个调用，两个结果交换 call_id 会怎样？

**参考答案。** 模型可能把结果归给错误动作，即使两份 JSON 都合法也会形成错误推理。Trace 必须保存调用身份、工具、参数和对应结果。当前适配器关闭并行调用，不代表可以省略关联键。

## 二、问题：严格 Schema 为什么还不能替代执行检查？

Schema 描述参数的形状，例如 `path` 是字符串。它不能单凭类型判断路径是否在允许目录、文件是否仍是刚读的版本，或训练预算是否充足。JSON 解析成功也只说明它是一份合法数据，不说明业务含义正确。[Python JSON 官方说明](https://docs.python.org/3/library/json.html)

当前代码做了两层控制：模型只看到任务允许的工具；执行时再次检查工具名，越权返回 `TOOL_NOT_ALLOWED`。补丁工具还核对编辑白名单、当前文件哈希，以及旧文本是否恰好出现一次。这些检查必须由程序负责，不能交给提示词保证。

**小例子。** 模型读取文件版本 h1，另一个动作修改成 h2；它再按 h1 提交补丁。即便补丁格式正确，也应拒绝，因为模型的判断基于过期源码。正确恢复路径是重新读取、理解当前内容，再生成修改。

**练习。** `{"path":"../../grader.py"}` 满足“path 为字符串”，是否可执行？

**参考答案。** 不可。执行层应拒绝越界和未登记路径。格式约束、路径边界、权限、数据协议和预算是不同检查；其中任何一层失败，都应返回可理解的结构化错误。

## 三、问题：怎样把“会改代码”变成可信的调试闭环？

先写可证伪假设，例如“低频商品的采样不足；增加其采样概率可能改善低频 Recall，但可能损害整体指标”。再产生真实 Diff，而不是只在报告里声称修改。验证分层进行：语法检查发现拼写或缩进；Smoke Test 检查张量形状与最小链路；短训观察能否学习；独立评分器判断预测质量。

`Workspace.validate()` 当前只检查语法，不执行候选代码。语法通过不能推出 PyTorch 维度正确，更不能推出 Recall 提升。训练失败时读取错误类型和相关栈帧，选择最小修复，再重新验证；不能为了消除报错而修改评分器或删除失败用户。

**设计伪例：**

```text
假设 → 读取源码 → 补丁 → 语法检查
→ 隔离 Smoke Test → shape 错误 → 最小修复
→ 短训 → 独立评分 → 接受或否定假设
```

**练习。** 修复后程序正常结束，但没有输出逐用户预测，可以报告实验成功吗？

**参考答案。** 只能报告进程运行结束，不能报告研究成功。还需验证产物完整性、用户覆盖和评价协议，由评分器重算指标；缺失产物是明确失败或未完成结果。

## 四、问题：Agent 为什么必须学会停下来？

模型重试可能修复暂时性 API 错误，却不能证明同一个代码错误再跑一次就会消失。`core/RunSession` 限制模型重试次数和总轮次；达到轮次上限返回 `step_limit_exceeded`，不会编造最终答案。`ResearchToolbox` 计数单实例中的补丁和实验尝试，并保守预留训练秒数；实际训练时间、费用和跨进程扣账仍需可信执行层。

`OptimizationAgent` 会在运行前注入研究计划和目标模型上下文，明确可编辑文件、允许候选与种子、基线、指标、协议和预算。模型提出的子任务计划或反思意见不能改变这些约束。目录重构不改变已有模型实验的训练/预测入口、评分协议和产物格式。

后续闭环应在动作前检查剩余预算，为已启动实验记账；失败实验消耗的时间同样计入。重复相同补丁、相同错误且没有新证据时，应停止或更换假设。耗尽预算后输出已有证据、未解决问题和最后状态。

**练习与参考答案。** 用完 3 次训练但未提升，是否自动加跑第 4 次？不可以。应报告负结果和预算边界。完成标准是诚实完成验证过程，不是保证取得正向提升。
