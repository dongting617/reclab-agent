### 先思考一个问题

两个月后你想重跑“提升低频推荐的最终实验”，却只找到一张表和`latest`镜像。源码后来改过，数据过滤规则也变了。表中的分数可能是真的，但你已经无法确定它对应哪个系统。可复现首先是定义清楚“到底运行了什么”。

### 原理：冻结的是实验身份

验证集结果复核前固定源码提交与补丁、依赖、镜像digest、数据与划分、商品映射、评价协议、配置、种子和权重。源码有未提交修改时，单记commit不够，还要保存补丁或完整快照。数据哈希能定位字节内容，但不能解释业务含义，因此还需保留预处理规则、候选集与历史过滤说明。

镜像tag可以指向新内容，digest用于识别固定内容；它仍不能代替宿主GPU、驱动和运行参数记录。[Docker镜像digest](https://docs.docker.com/dhi/explore/security-concepts/digests/)

设计示例：

```text
ExperimentIdentity = {
  source_snapshot, data_manifest, split_manifest,
  image_digest, evaluator_version, config, seed
}
```

这种身份记录让别人能找到同一个实验，不保证跨硬件逐位一致。固定随机数也不能消除所有算子、平台和版本差异。[PyTorch复现说明](https://docs.pytorch.org/docs/2.14/notes/randomness.html)

### 原理：单个随机种子的验证集评估与用户bootstrap

默认基线与候选使用同一个固定随机种子各训练一次，再在同一验证集上独立评估。例如基线NDCG@20为0.10、候选为0.11，绝对变化为+0.01，相对变化为+10%。该结论限定于已记录的数据、配置和种子，不要求额外运行三个seed，也不据此宣称跨种子稳定收益。

用户bootstrap在固定已训练模型上重采样验证用户，估计当前用户样本对指标差异的不确定性。它不会重新训练模型，不增加训练种子，也不能证明跨种子稳定。共享训练模型的数千个用户不能当作数千次独立训练；报告验证集总体及分桶指标，并明确单个种子的结论范围。

项目统一使用验证集进行checkpoint选择、候选比较和结果复核，不要求另行测试集评估。交付时冻结源码、配置、种子、权重和验证集评分证据；验证集参与选择，因此不将其分数声称为独立测试集上的泛化结果。

### 原理：Adapter迁移是协议迁移

Agent核心负责规划、调用、预算与证据，Adapter负责把新模型接到统一训练、预测和产物协议。换序列推荐模型时，适配源码入口、配置和依赖；换数据时，适配交互、映射、时间划分与可用特征。评分器只在评价任务相同时复用。

例如从SASRec换GRU序列模型，可以继续输出商品排名并计算NDCG；改成点击率预估，则需明确概率输出、样本与曝光语义、AUC/Logloss等协议，不能直接套Top-K结果。接入完成只能证明能研究它，不能保证找到有效改进。

### 在RecLab里边学边做：建立证据链

选择一个没参与开发的新模型或数据集，先跑基线，再让核心Agent用同一套接口提交一个受控实验。记录改了哪些Adapter、哪些核心代码没改、哪些环节失败。只有实际完成后才能声称迁移验证通过。

简历中“实现”“验证”“提升”应分别对应代码、运行记录和对照结果。一个真实失败案例也有价值：例如候选的验证集NDCG提高，但Recall保护指标下降，最终回退。讲清假设、修改、比较、否定理由和成本，比隐藏失败更能证明研究判断。

1. “单个seed的用户bootstrap区间为正，所以跨种子稳定提升”有什么问题？
2. 已留模型权重，可以省略数据划分和源码快照吗？
3. 只预留MLE-bench接口，应如何写简历？

### 参考答案

1. 用户bootstrap只反映固定模型下的用户抽样不确定性，不反映重新训练的波动；单个seed不能支持跨种子稳定提升。
2. 不可以。权重不能说明数据是否泄漏、如何生成预测、评分口径是否一致。
3. 可写“抽象实验执行与评分接口，支持后续适配”，不能写“完成MLE-bench评测”。PRTA、生产上线和强化学习同样按实际证据表述。

周末自检：挑一条简历陈述，能否一路指向任务、Diff、身份记录、日志、独立分数与结论？不能的地方补证据或收窄表述，不补想象中的结果。

### 本周概念检查清单

- 冻结与验证集评估：保留源码、配置、种子、权重、环境和验证集评分证据。
- 泛化与迁移：能接新模型/数据不等于自动提升；评价任务改变时必须适配评分器。
- 能力证据表达：讲清问题、设计取舍、真实结果、失败和局限，不把计划写成已实现。
- 项目边界：PRTA与MLE-bench作为后续适配，只有接口预留不能声称完成官方评测。

## 边学边做

- 对冻结B1与最终候选使用同一个固定随机种子各训练和验证集评估一次，报告NDCG/Recall及分桶指标；无提升也保留结论。
- 接入一个未参与开发的新模型或数据集，验证核心Agent无需改写即可开展实验。
- 整理真实成功与合理失败案例，录制问题—补丁—实验—证据—结论演示。
- 更新README、环境锁定、运行说明、作品介绍和面试问答，逐项核对实现与验证状态。
