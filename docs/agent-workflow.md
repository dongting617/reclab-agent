# Agent 工具、研究流程与代码职责

本文件是当前项目的研究接入合同。默认诊断 CLI 注册 6 个只读证据工具。框架已支持 ReAct、计划执行和 Reflection 等策略，可选 `ResearchToolbox` 将已有工作区、计划审阅和实验回调接入这些策略；Docker 训练、预测、独立评分与实际费用控制由宿主配置的可信 runner 负责。八阶段表仍是研究规范，并非可持久恢复的自动研究状态机。实现入口与边界见[Agent 框架与扩展](agent-framework.md)。

## 一、基本流程

目标是围绕推荐模型提出可检验方案，在明确条件下验证，交付有证据的结论及可复现代码。有效负结果和“不足以下结论”都可以正常完成研究任务。

| 阶段 | 输入与动作 | 必须保存的结果 |
|---|---|---|
| 明确任务与上下文 | 确定数据 Profile、基线、主指标、约束指标和预算；核对已有基线身份及评价协议 | 任务目标、基线引用、评价条件和资源限制 |
| 诊断、优化设想与取证 | 阅读源码、实验结果和登记资料；交替提出问题、优化设想并检查支持及反对证据 | 已确认事实、待验证假设和证据缺口 |
| 设计实验与审阅计划 | 明确候选修改、对照、预期观察、判定规则、允许修改范围及停止条件 | 带版本的研究计划与用户审阅记录 |
| 实现与程序验证 | 应用补丁，保留真实 Diff；静态检查后在隔离环境做最小运行验证 | 候选快照、检查结果、错误及修复记录 |
| 实验与独立评分 | 复用身份匹配的基线或运行对照；隔离训练、独立预测、外部固定评分 | 作业、权重、预测、评分及成本引用 |
| 结果分析与决策 | 比较总体、分桶、约束指标和开销；判断假设获得支持、被反驳或尚不确定 | 保留、否定、继续调查或停止的理由 |
| 复核与确认 | 按已批准范围和预算进行重复种子、必要消融或完整训练；最终测试前冻结方案 | 更强结论及适用边界，或明确待确认项 |
| 交付与经验积累 | 报告结论、证据、代码差异、复现方式和限制；保留负结果及失败条件 | 可复核报告、产物引用和带条件的研究记录 |

诊断和优化设想没有固定先后顺序。可以从异常观察提出假设，也可以从用户方案或理论先验出发，再寻找验证依据。提交实验计划前只要求方案可检验、对照清楚、判断规则明确，不要求提前证明优化一定有效。

程序运行失败进入调试与修复分支；有效实验未提升进入结果分析分支。两者分别保存。`completed` 表示执行完成，不表示推荐效果提高。

## 二、什么是足够的证据

每项实测结论应指向可核验的产物版本或哈希、JSON Pointer 或代码位置，并记录数据、协议、源码、配置、种子等适用条件。报告同时保留矛盾证据和未完成验证。

| 结论种类 | 可以声称什么 | 还不能据此声称什么 |
|---|---|---|
| 可定位的观察 | 固定验证集及协议下，某分桶指标或代码行为具有某种表现 | 已发现唯一原因，或历史结果适用于当前候选 |
| 待检验的推断 | 某种采样、损失或结构调整有理由值得实验 | 该机制已经被证明，或方案必然有收益 |
| 有效对照实验 | 在记录的条件下，候选与基线的指标、成本存在给定差异 | 单次结果等于稳定收益，或离线差异等于线上收益 |
| 重复或机制验证 | 重复种子支持一定训练稳定性；相应消融支持特定解释 | 超出这些数据、配置与验证范围的普遍结论 |

程序验证回答“是否按协议正确运行”；效果验证回答“在当前条件下是否优于基线”；机制验证回答“为什么产生差异”。需要解释机制时才增加对应验证，不把因果证明作为首次实验门槛。

现有 `compare_reports` 的配对用户 bootstrap 反映用户抽样不确定性，不能代替重复训练种子的稳定性检查；不同 Profile、用户、目标、过滤规则或评分协议不能直接比较。具体口径见[独立评分协议](grading-protocol.md)。

## 三、工具目录

能力目录由 `reclab_agent.tools.tool_catalog()` 提供，条目包含 `name`、`group`、`availability` 和 `responsibility`。`available` 表示当前已注册，`planned` 表示待接入。目录不是执行注册表，只有 `RecLabToolbox.specs` 中的工具会被转换成模型函数定义。

| 分组 | 工具 | 状态与职责 |
|---|---|---|
| 证据 | `list_evidence`、`inspect_artifact` | 已注册：发现证据并检查身份、文件大小及 JSON 元信息 |
| 证据 | `read_json_values`、`compare_numeric_values` | 已注册：按 Pointer 读取实测数值并做确定性比较 |
| 专项诊断 | `diagnose_beam_gap`、`diagnose_frequency_gap` | 已注册：分析项目内固定 G2/B1 报告，不是通用研究的必经阶段 |
| 知识 | `search_knowledge` | 待接入：检索登记资料，返回来源、位置和版本 |
| 工作区 | `search_source`、`read_source` | 待接入：定位并读取登记的候选源码和配置，返回内容身份 |
| 工作区 | `apply_patch`、`validate_candidate` | 待接入：在批准范围内应用哈希校验补丁，返回真实 Diff，并检查语法与入口协议 |
| 实验 | `submit_experiment`、`get_experiment`、`cancel_experiment` | 待接入：提交已批准实验，查询状态、有限日志和产物，取消并报告实际停止确认状态 |
| 评测 | `compare_experiments` | 待接入：读取独立评分报告，核验比较条件，返回整体、分桶及适用的不确定性分析 |

“诊断”“思考”“提出假设”“解释结果”是 Agent 的推理职责，不另建空泛工具。研究计划和研究结论采用结构化输出，由协调器保存，也不需要模型逐步调用“算哈希”“记预算”“冻结源码”等内部操作。

上述目录描述默认证据工具箱。可选 `ResearchToolbox` 额外提供 `read_source`、`apply_patch`、`validate_candidate`，配置可信 runner 后再提供同步 `run_experiment` 与 `get_experiment`。它不将目录中的异步 `submit_experiment` 自动接上线；未实际注册的名称仍返回 `UNKNOWN_TOOL`。

## 四、按研究计划审阅

用户先审阅一份研究计划，计划至少包含：问题及假设、证据与缺口、基线/数据/协议引用、候选上限、允许修改的文件、对照与判定规则、资源预算及停止条件。

批准的是这份计划及其版本所界定的范围，不是每一条训练命令。范围内允许自动修复程序问题、执行批准的候选及重复实验。更换研究假设、增加候选、超出文件或实验配置范围、增加预算时，应形成新版本并重新审阅。确认实验若不在原计划和预算内，也需另行审阅。

在审阅前可读取上下文和搜集依据；修改候选和启动实验属于审阅后的动作。缺少匹配基线时，复现基线本身应进入计划并计入预算。已有、身份匹配的基线可以复用，不能只因为名称相同就复用。

上述审阅、动作校验与预算扣账是研究协调器的接入要求。可选优化工具会在写入和运行前校验匹配的 `PlanReview`，计数单实例中的补丁、实验尝试和预留训练秒数。审阅记录由可信宿主传入，模型生成的计划或反思不能自行批准执行；跨进程预算和实际费用执行仍需协调器与 runner。

## 五、Agent 与系统的责任

Agent 负责提出假设、选择证据、设计修改、解释有效实验和建议下一步。协调器负责阶段依赖、计划审阅状态、权限和预算等可计算约束，不能仅依赖 Prompt 提醒。

当前 `OptimizationAgent` 会在运行前注入任务、研究计划及目标模型上下文：可编辑文件、允许候选与种子、基线、数据 Profile、评价协议、指标和预算由可信宿主提供，模型无需猜测工具参数。这不代表八阶段研究状态机已经实现，也不赋予模型自行批准研究计划的权限。

完整协调器接入后还应自动完成：

- 注入任务上下文、登记资源、历史状态和剩余预算；只向模型提供当前阶段允许且实际已注册的工具。
- 校验可修改范围和计划版本，冻结源码并绑定数据、配置、镜像、种子与实验身份。
- 幂等提交，断线后先查已有作业；启动预测和外部评分，保存完整产物引用。
- 为模型调用、补丁、失败训练、修复重跑和确认实验分别按其资源消耗记账；不自动扩大预算。
- 监督超时与取消；停止未确认时保留真实状态，不把断线等同于训练退出。
- 冻结最终方案后才通过可信流程做最终测试，不向模型开放任意测试标签读取或调参接口。

当前 `Budget` 默认限制 3 次训练、单次 600 秒、总训练 1800 秒、6 次补丁和 20 元成本，但声明这些字段不等于执行层已经统一扣账。基线和候选各多种子确认可能超过开发预算；只能复用匹配基线或另行批准确认预算，不能悄悄追加实验。

达到目标、预算耗尽、重复相同失败且没有新证据、无法取得必要依据或执行环境不可用时停止，报告已有事实和未完成项。停止原因不改变有效负结果的价值。

## 六、代码职责与实施边界

| 位置 | 职责 |
|---|---|
| `core/` | 统一 Agent 与模型接口、共享会话、工具执行权限、轮次和 Trace |
| `agents/` | Simple、ReAct、PlanExecute、Reflection 的可运行策略 |
| `tools/` | 公开工具包：工具契约、注册表、现有证据工具及能力目录 |
| `research/` | 研究契约、八阶段规范及可选 ResearchToolbox/OptimizationAgent；不代替持久化实验协调器 |
| `execution.py` / `_execution/` | 保留公开 Worker API；拆分执行数据类型、Docker 适配、跨进程锁和 Policy 加载 |
| `files.py` | 共享文件与路径校验；旧模块保留兼容导出 |
| `workspace.py`、`retrieval.py` | 候选工作区和登记知识检索的底层能力 |
| `grading.py`、`datasets.py`、`storage.py` | 固定评价、可信数据适配、产物与运行状态保存 |

`ResearchStage` 和阶段工具权限表描述未来协调器的动作边界，不代表现有 Agent 已经按阶段调度。研究计划、实验记录和研究结论与既有 `TaskSpec` / `JobSpec` 分开，避免改变历史作业身份和存储格式。

Python 使用方从 `core`、`agents`、`tools` 和 `research` 取得对应接口；旧 `AgentRuntime` 名称及 `reclab_agent.runtime` 导入不再保留。原实验的训练/预测入口、数据和评分协议、Worker 身份及产物格式保持不变。

这些契约已提供可独立使用的检查：`ResearchPlan.validate_for_task(task)` 核对任务身份和预算上限；`plan_hash` 绑定整份计划，包括候选、文件、种子、判断规则和预算。可信入口记录用户审阅后，`require_plan_approval(plan, review)` 拒绝缺失、否定或内容已经变化的审阅记录，`plan.check_scope(...)` 核对候选、文件、种子及确认实验范围。它们不认证审阅者，也不代替协调器的权限、实时预算与状态管理，不能由模型自行生成一个 `PlanReview` 就获得执行权限。

三类主要契约均可通过 `to_dict()`、JSON 和 `from_dict()` 往返，并复用 `ArtifactStore.put_json()` 保存，无需迁移现有数据库。`ExperimentRecord` 只有在程序验证通过、训练与预测作业引用完整且存在独立评分产物时才接受 `completed`；执行失败不能携带有效评分。`ResearchConclusion` 将观察、推断和假设分别标记，观察必须带证据引用，负结果和不确定结果均可正常记录。

完整接入仍需：把实验回调绑定到真实模型的隔离训练/预测/独立评分，接入检索与可持久恢复的研究协调器，完成实际费用执行和真实模型闭环验收。现有合成 Demo 是固定训练→预测→评分 fixture，明确 `llm_connected=false`，不能作为自主研究完成证据。

本次结构回归重点是规范模块导入、既有 6 工具行为、实验持久化兼容及打包完整。Agent 旧入口的迁移应与实验协议兼容分别检查。后续完整闭环还需覆盖：两种研究起点、未审阅拒绝执行、范围内修复、有效正/负/不确定结果、协议不匹配拒绝比较、恢复不重复训练、预算耗尽及证据可追溯。真实容器、GPU 和推荐质量验收应分别报告，不能由 FakeDocker 测试推出。
