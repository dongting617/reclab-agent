# 第一天多角色失败审计与修复

本轮从历史冻结报告的七个失败开始，离线复现错误归因并修复确定性处理缺陷。没有新增模型请求或 GPU 作业，没有重新评分或覆盖原来的 23/30 成绩。详见[逐例审计与来源哈希](day1-failure-audit-20261124.json)。

| 失败类别 | 数量 | 核验结果与处理 |
|---|---:|---|
| 最终答案包含解释文字和 JSON | 3 | 检查点保留原文；不符合冻结输出契约，仍判格式失败，不截取其中 JSON 来提高成绩 |
| Planner 输出非法 JSON | 1 | Agent 已返回 invalid_plan，旧评测器又解析空答案，掩盖了主要失败原因；现在保留角色终止状态，空答案不再送入 JSON 解析 |
| 模型服务超时 | 2 | 分别发生在执行和复核阶段，失败预留仍计入原预算；复核超时案例的草稿本身也有错误，不能假定网络恢复即可通过 |
| 判断与引用错误 | 1 | 模型忽略停止未确认的证据，仍然保留候选；这是模型判断错误，未通过解析器修补或重跑消除 |

## 实际修改

- 通用模型轨迹增加当前轮 `output_text`，便于定位格式失败；诊断报告保存 `raw_answer`，不记录客户端配置或认证信息。
- 诊断评测分别报告角色终止、JSON/答案结构、服务、预算及判断/引用问题。错误保留 Trace 路径和耗时；角色检查点存在时补充阶段信息。
- Reviewer 缺少 feedback、角色提交缺少 arguments 均成为明确的非法输出状态。前者是代码审查发现并补充的确定性用例，不是上述七例的历史归因。
- 本地预算拒绝以 `request_not_sent` 标记，避免没有送出的请求被当作 API 使用量，也不进行无效重试。已经预留的角色额度不回滚，原会话预算不重置。
- 新错误报告策略绑定 `typed_failures_and_raw_answers_v2` 身份。旧任务、标签、Prompt、严格 JSON 规则和历史成绩保留；新代码拒绝覆盖旧身份输出文件。

保存四条实际模型输出作为离线回归 fixture，新增九项相关测试。第一轮定向 37 项测试通过；最新全量结果同步记录在 README 与优化记录中。这里的成功说明错误处理路径通过确定性验证，不是多角色模型评分提高。
