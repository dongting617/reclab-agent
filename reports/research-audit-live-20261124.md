## 失败与审计

- dev / react：失败分类 `{"CITATION_INVALID_OR_NOT_LOCATED": 1}`。
- dev / research_audit：失败分类 `{"invalid_audit": 2, "PROVIDER_TIMEOUT": 2, "CITATION_INVALID_OR_NOT_LOCATED": 3, "audit_inconclusive": 2, "INCORRECT_DECISION": 1}`。
  审计前正确且引用达标 24 例，其中未放行 4 例；有效格式的错误决策 2 例，审计批准 1 例。
  正确回答未放行中，审计判断造成 1 例，其余属于提交协议或服务失败。
  决策正确但引用不达标且被审计批准 3 例。
  最终答案格式不合法 0 例，其中审计批准 0 例；终端严格解析仍会将其计为失败。
- frozen / react：失败分类 `{"REQUEST_LIMIT": 18}`。
- frozen / research_audit：失败分类 `{"REQUEST_LIMIT": 30}`。
  审计前正确且引用达标 0 例，其中未放行 0 例；有效格式的错误决策 0 例，审计批准 0 例。
  正确回答未放行中，审计判断造成 0 例，其余属于提交协议或服务失败。
  决策正确但引用不达标且被审计批准 0 例。
  最终答案格式不合法 0 例，其中审计批准 0 例；终端严格解析仍会将其计为失败。

审计模式目前没有自动修订：它可以拦截结论，但不会改写研究者答案。判断收益需同时考虑错误放行、正确结论误拦和资源消耗。

原评分器遇到无效引用时可能同时将 decision_correct 置为 false。这里用冻结答案独立核对决策，单独归因为引用错误；不改变原始通过数、原始失败字段或报告。

原始批次 model_requests 是局部预留计数：截止后本地拒绝也可能先占用一次局部计数。汇总以 Trace 计数和全局请求账本核对，不把这些本地拒绝算作已调用 API。

## 当前结论与后续

本次完整覆盖的开发集不支持切换默认模式。审计组在进入审计门禁前已有部分回答未达到严格评分条件，因此不能把全部差异归因于审计门禁。正确回答未放行也要区分审计判断、提交协议与服务失败。
优先修复审计提交协议、引用检查及失败归因，复核超时与输出长度，再在新协议和新额度下测评。已观察过的失败可作为开发用例，不把重跑成绩覆盖本轮。

- 本轮未使用远程 GPU。CPU 编码未运行：原缓存镜像不可用；没有下载镜像或改用宿主执行候选代码。

- 原始失败与 Trace 保留，不补跑失败或覆盖报告提高分数。
- 原始汇总：`research-audit-live-20261124.json`；逐任务结果与审计见同名前缀的 JSON 和被忽略的 `*-traces/`。
